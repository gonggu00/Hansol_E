[v3.8 변경사항 - 페이지 넘길 때 하얗게 비어보이는 버퍼링 현상 수정]
기존에는 책을 여는 순간 215페이지 이미지를 전부 "우선순위 없이" 브라우저에
한꺼번에 맡겨서, 지금 보는 페이지 근처가 늦게 로딩되며 페이지를 넘길 때
왼쪽 페이지가 1~2초간 하얗게 비어보이는 문제가 있었습니다. 아래와 같이
"가까운 페이지부터 확실히 먼저" 불러오도록 구조를 바꿨습니다:

1. 책을 여는 즉시, 첫 화면 근처(앞뒤 4페이지)를 최우선으로 즉시 프리로드합니다.
2. 페이지를 넘기기 "시작하는 순간"(애니메이션이 끝나기 전) 도착할 페이지
   주변을 미리 불러오기 시작해서, 애니메이션이 끝날 때쯤엔 이미 준비되도록
   했습니다.
3. 나머지 전체 페이지는 화면이 한가한 틈(requestIdleCallback)에 화면 끊김
   없이 백그라운드로 순서대로 계속 미리 불러옵니다.
4. 기존에 페이지를 표시하던 방식(background-image)은 그대로 유지하고,
   그 위에 프리로딩만 추가했습니다 - 기존 표시 로직은 건드리지 않았습니다.

검증: node --check로 문법 오류 없음 확인, 기존 app.js 코드는 한 줄도
삭제되지 않고 74줄만 순수 추가된 것을 diff로 확인 (기존 기능 보존).
실제 기기에서의 체감 속도 개선은 사용자 직접 확인이 필요합니다.

[v3.7 변경사항 - 별도 조치 없이 실행할 때마다 자동으로 캐시 정리]
지금까지는 새 버전을 올린 후 "브라우저 설정에서 캐시를 수동으로
지워야" 확실하게 반영됐는데, 이제 카탈로그를 실행할 때마다 아래
과정이 전부 자동으로 일어나도록 했습니다:

1. 서비스워커 스크립트 자체를 브라우저가 임의로 캐시하지 못하게 막아서,
   항상 최신 서비스워커 파일을 확인하도록 했습니다.
2. 카탈로그를 실행하는 즉시, 새 버전이 있는지 능동적으로 바로 확인합니다
   (브라우저가 알아서 나중에 확인할 때까지 기다리지 않음).
3. 새 버전의 서비스워커가 실제로 이 화면을 담당하게 되는 순간, 화면을
   자동으로 한 번 새로고침해서 예전 캐시가 완전히 정리된 새 화면으로
   자동 전환합니다.
4. 위 서비스워커 절차와 별개로, 카탈로그가 열리자마자 이 화면에서 직접
   "지금 버전과 이름이 다른 예전 캐시"가 있는지 확인해서 즉시 지웁니다
   (서비스워커의 활성화 타이밍을 기다리지 않는 이중 안전장치입니다).

이제 사용자님이 별도로 캐시 삭제 방법을 안내해드리지 않아도, 카탈로그를
열기만 하면 최신 버전이 자동으로 반영됩니다.

검증: 가짜 캐시 저장소를 만들어서 "예전 버전 캐시만 정확히 지워지고,
현재 버전 캐시와 무관한 다른 캐시는 그대로 유지되는지" 확인. 목차
이동(신발장A→44p), 페이지4 색인 등 기존 기능도 재확인 (오류 0건).
